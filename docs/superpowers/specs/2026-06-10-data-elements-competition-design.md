# "安全智脑" — 2026年数据要素×大赛吉林省分赛 参赛方案

## 概述

- **比赛**：2026年"数据要素×"大赛吉林省分赛
- **赛道**：赛道九（应急管理）→ 赛题一「提升安全生产监管能力」
- **方向**：高危行业（危险化学品/化工建设）安全生产监管
- **项目**："安全智脑"——面向高危行业的安全生产知识智能体
- **基底项目**：knowledge-manager v0.5.1（已有 ~417KB Python源码，29模块，75+测试）
- **目标**：冲奖

## 赛道要求（原文）

> 围绕矿山、危险化学品、烟花爆竹、重点工贸等高危行业安全生产监管需求，以及城市（超）高层建筑、地下空间、交通枢纽、劳动密集型企业、重点文物保护单位、经营性自建房、室内冰雪娱乐场所、医院病房楼等高风险聚集场所消防安全风险预警需求，构建安全风险预警和隐患智能感知模型，辅助识别潜在安全风险和疑似违法违规行为。

## 核心定位

将企业碎片化的安全规章制度、检查记录、事故报告转化为可推理、可检索、可进化的结构化知识系统，赋能一线安全管理人员实现风险智能识别与合规辅助决策。

## 核心叙事（评审主线）

| 层 | 痛点 | 方案 | 数据要素×效应 |
|----|------|------|-------------|
| 数据层 | 安全数据散落在制度文件、检查台账、事故报告中，格式不一，利用率低 | LLM自动提取为结构化知识模块，人工审核门控保证质量 | 一次提取，多次复用；单点知识，全局共享 |
| 知识层 | 安全检查依赖个人经验，新人上手慢，老专家知识难以传承 | 知识树导航 + 多路检索 + 语义矛盾检测，实现"老专家的经验随时可查" | 隐性知识显性化，个体经验组织化 |
| 决策层 | 隐患排查存在盲区，同类事故反复发生 | 基于知识图谱的风险关联推理，匹配最新法规标准 | 被动响应→主动预防 |

## 差异化亮点

1. **不是又一个RAG** — 覆盖"提取→审核→结构化→矛盾检测→记忆强化"的完整知识生命周期，而非简单的文档切片+向量检索
2. **MCP协议原生支持** — 知识可被AI Agent直接调用，作为任何安全智能体的知识底座，符合"数据基础设施"方向
3. **已有行业落地基础** — 50+化工安全知识模块已入库，不是凭空PPT

## 功能模块详述

### 核心功能（比赛重点展示）

**1. 风险智能识别** — 需新建风险规则引擎

- 输入：自然语言描述的场景（如"明天要在3号罐区进行焊接作业"）
- 处理：知识库检索 → 匹配动火作业安全规程 → 识别该场景下的风险项
- 输出：风险清单（风险项 + 等级 + 依据来源模块 + 建议控制措施）
- 技术：LLM查询改写 + 知识树导航 + 多路检索融合（已有）+ 风险规则匹配（需新建）

**2. 合规在线检查** — 需新建合规对照引擎

- 输入：企业安全规程文本 / 检查记录
- 处理：LLM提取关键要求 → 与国标/行标知识库对照 → 标记差距
- 输出：合规差距报告（缺失项 + 冲突项 + 更新建议）
- 技术：语义矛盾检测（已有 lint --deep）+ 法规标准知识库（需补充L1数据）

**3. 应急方案推荐**

- 输入：事故类型 + 现场条件（如"储罐区化学品泄漏，风向东南风"）
- 处理：知识树导航定位应急预案模块 → 匹配现场条件 → 推荐响应流程
- 输出：应急步骤清单 + 所需物资 + 人员配置建议 + 注意事项
- 技术：知识树推理导航（已有 tree_navigator）+ 条件匹配逻辑

### 附属功能（提及但不重点演示）

**4. 培训知识卡片** — 基于FSRS间隔重复（已有），定位为"安全培训辅助"

**5. MCP Agent接口** — 已有完整MCP Server实现，展示AI Agent调用安全知识的场景

### 关键演示案例

**受限空间作业全流程知识链路**（贯穿所有功能的黄金演示路径）：

```
GB 30871 受限空间条款
  → 企业作业票制度
  → 气体检测标准（O₂/可燃气/H₂S/CO阈值）
  → 监护人双岗职责
  → 2小时复测要求
  → 应急救援预案（含物资清单）
  → [如有] 历史事故案例关联
```

## 数据策略

### 三层数据架构

| 层级 | 来源 | 内容 | 确定性 | 作用 |
|------|------|------|--------|------|
| L1 | 公开法规标准 | GB 30871、AQ标准、应急管理部令等 | ✅ 可获取 | 合规对照引擎的数据基础 |
| L2 | 通用安全规程 | 50+化工安全知识模块 | ✅ 已有 | 系统核心知识库 |
| L3 | 企业脱敏案例 | 检查记录、隐患台账、事故报告（脱敏） | ❓ 待对接 | 差异化竞争力的关键 |

### 三套应对预案

**方案A（最优 — 拿到企业数据）**
- 将脱敏后的检查记录/隐患台账作为真实数据源展示
- 演示：导入某化工企业安全检查记录 → 自动提取隐患模式 → 与国标对照 → 生成整改优先级
- 提供量化对比：人工整理耗时 vs 系统处理耗时、遗漏率对比

**方案B（次优 — 企业只给案例不给数据）**
- 用1-2个真实事故案例做深度拆解演示
- 强调知识深度和推理质量
- 引用企业人员的评价/推荐信

**方案C（保底 — 无企业数据）**
- 完全基于公开法规和通用安全规程构建演示
- 核心卖点转为："即使只有公开数据也能快速构建安全知识底座，企业接入自身数据后立即增值"
- 覆盖多行业（化工/建筑）展示广度

## 评审风险与应对

| 风险 | 应对 |
|------|------|
| 评委认为"不就是个RAG吗" | 强调知识生命周期完整性（提取→审核→结构化→矛盾检测→记忆）；展示MCP协议原生支持 |
| 缺少真实企业数据 | 准备方案C保底策略；用公共标准的完整性来弥补 |
| 无法展示可量化效果 | 至少做模拟数据的Before/After对比；强调"企业接入自有数据后的增值潜力" |
| 应急管理赛道评委更关注硬件/IoT | 明确定位为"知识层"而非"感知层"；说明可与已有监测系统对接 |
| 大厂碾压 | 强调轻量化、可私有部署、MCP协议标准化的差异化优势 |

## 不做的事

- 不开发硬件/IoT对接（定位在知识层，说明可对接即可）
- 不开发移动App（Web优先，移动端仅做适配演示）
- 不追求全行业覆盖（聚焦危化品/化工建设，深度优先于广度）
- FSRS间隔记忆不作为核心亮点（降级为附属功能，防止焦点分散）
