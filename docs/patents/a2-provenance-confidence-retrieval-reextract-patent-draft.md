# 发明专利申请文件初稿 A2

> 文档用途：供专利代理人修改、检索和定稿。本文不是正式法律意见，也不建议在未完成新颖性检索和未公开实现确认前直接提交。

## 发明名称

一种基于溯源置信度的知识模块检索抑制与自动重抽取触发方法、装置、电子设备及存储介质

## 摘要

本发明公开了一种基于溯源置信度的知识模块检索抑制与自动重抽取触发方法、装置、电子设备及存储介质。该方法包括：接收知识检索请求并生成候选知识模块集合；获取候选知识模块的溯源元数据，所述溯源元数据包括源文档版本、源文档校验值、源片段覆盖率、抽取时间、审核状态、失效状态或历史使用反馈中的至少一种；根据所述溯源元数据计算候选知识模块的溯源置信度分值；根据查询任务类型或风险等级确定置信度阈值；依据所述溯源置信度分值和所述置信度阈值控制候选知识模块的召回状态；当候选知识模块满足重抽取触发条件时，根据其关联的源文档或源片段生成重抽取任务。通过本发明，检索系统不仅根据相关性召回知识，还根据知识模块的当前可信程度进行召回控制，从而降低低可信、过期或源不一致知识进入智能体或大语言模型上下文的概率。

## 说明书

### 技术领域

本发明涉及信息检索、知识库治理、大语言模型上下文管理、智能体知识调用和文档同步领域，尤其涉及一种基于溯源置信度的知识模块检索抑制与自动重抽取触发方法、装置、电子设备及存储介质。

### 背景技术

面向智能体和大语言模型的知识系统通常需要从结构化或非结构化文档中抽取知识，并将知识保存为可检索的知识模块。检索系统可以根据关键词匹配、语义向量、图关系、历史反馈或字段权重等方式召回候选知识模块，再将候选知识模块提供给智能体或大语言模型使用。

然而，在实际运行中，知识模块的相关性并不等同于可信性。一个知识模块即使与当前查询高度相关，也可能因为源文档已经更新、源片段丢失、抽取时间过久、审核状态不足、模块已被标记失效或历史反馈异常而不适合继续被召回。传统检索系统通常依赖静态状态字段或人工审核结果，难以在每次检索时动态评估知识模块的当前可信程度。

特别是在高风险任务中，例如生产故障处理、部署操作、权限配置、合规判断或安全处置，低可信知识被输入到智能体或大语言模型上下文中可能导致错误操作。因此，需要一种能够在检索阶段结合溯源元数据动态计算知识模块可信程度，并据此控制召回、排序、抑制和重抽取触发的技术方案。

### 发明内容

#### 要解决的技术问题

本发明要解决的技术问题是：如何在知识检索阶段动态评估候选知识模块的当前可信程度，并根据可信程度和任务风险控制候选知识模块的召回状态，同时在低可信场景下自动触发重抽取任务。

#### 技术方案

为解决上述技术问题，本发明提供一种基于溯源置信度的知识模块检索抑制与自动重抽取触发方法。该方法在接收到知识检索请求后，先通过关键词检索、语义检索、图关系检索或混合检索生成候选知识模块集合。随后，系统获取各候选知识模块的溯源元数据，溯源元数据可以包括源文档版本、源文档校验值、源片段覆盖率、抽取时间、最近同步时间、审核状态、失效状态、模块置信度和历史使用反馈。

系统根据溯源元数据计算各候选知识模块的溯源置信度分值。该分值用于表示候选知识模块在当前时刻相对于其来源文档和使用场景的可信程度。系统根据查询任务类型或风险等级确定置信度阈值，并将溯源置信度分值与置信度阈值进行比较，从而确定候选知识模块的召回状态。

候选知识模块的召回状态可以包括正常召回、降权召回、附带提示召回、抑制召回和触发重抽取。对于满足重抽取触发条件的候选知识模块，系统根据其关联的源文档或源片段生成重抽取任务。重抽取任务可以进入暂存区或审核队列，审核通过后更新知识模块、搜索索引和搜索投影。

#### 有益效果

与现有技术相比，本发明至少具有以下有益效果：

1. 将知识模块的溯源可信程度引入检索阶段，使检索系统不再只根据相关性召回知识。
2. 能够针对高风险任务提高召回可信度门槛，降低低可信知识进入智能体或大语言模型上下文的概率。
3. 能够自动识别需要重抽取的知识模块，缩短从源文档变化到知识模块修复的时间。
4. 通过记录召回控制原因码，提高检索治理、审核和调试的可解释性。

### 具体实施方式

以下结合附图和实施例对本发明进行说明。应当理解，所描述的实施例仅用于解释本发明，而不用于限定本发明的保护范围。

#### 实施例一：候选知识模块生成

系统接收知识检索请求。该知识检索请求可以来自智能体、大语言模型上下文加载器、问答系统、命令行工具或网页服务。系统根据知识检索请求生成候选知识模块集合。

候选知识模块集合可以通过关键词匹配、字段权重检索、语义向量检索、图关系扩展、历史反馈排序或多路融合检索生成。本实施例不限定候选集合的具体生成方式。

#### 实施例二：溯源元数据获取

对于候选知识模块集合中的每个候选知识模块，系统获取其溯源元数据。溯源元数据可以包括：

```text
source_document_id: 源文档标识
source_version: 源文档版本
source_checksum: 源文档校验值
span_coverage: 源片段覆盖率
extracted_at: 抽取时间
last_synced_at: 最近同步时间
review_status: 审核状态
stale_state: 失效状态
module_confidence: 模块置信度
usage_feedback: 历史使用反馈
```

其中，源片段覆盖率可以表示候选知识模块当前可追溯到有效源片段的内容比例。历史使用反馈可以表示用户或智能体在历史检索后是否加载、确认或拒绝该候选知识模块。

#### 实施例三：溯源置信度计算

系统根据溯源元数据计算溯源置信度分值。溯源置信度分值可以通过规则、加权公式、机器学习模型或二者组合计算。

在一个实施例中，系统可以按照如下方式计算：

```text
provenance_confidence =
  version_score       * w1
+ checksum_score      * w2
+ span_coverage_score * w3
+ freshness_score     * w4
+ review_score        * w5
+ feedback_score      * w6
- stale_penalty       * w7
```

其中，`version_score` 表示源文档版本一致性，`checksum_score` 表示源文档或源片段校验一致性，`span_coverage_score` 表示源片段覆盖程度，`freshness_score` 表示抽取结果的新鲜度，`review_score` 表示审核可信度，`feedback_score` 表示历史使用反馈可信度，`stale_penalty` 表示失效状态惩罚值，`w1` 至 `w7` 为权重。

在另一个实施例中，系统可以按查询任务类型使用不同权重。例如，在故障处理任务中提高源版本一致性和审核状态的权重；在探索查询中提高相关性权重并降低置信度阈值。

#### 实施例四：动态阈值确定

系统根据查询任务类型或风险等级确定置信度阈值。风险等级可以包括低风险、中风险和高风险。高风险任务可以对应更高的置信度阈值。

例如：

```text
low_risk_threshold: 0.45
medium_risk_threshold: 0.65
high_risk_threshold: 0.82
```

当查询任务为生产部署、故障处理、安全配置或合规判断时，系统可以将其识别为高风险任务。当查询任务为一般知识浏览或探索查询时，系统可以将其识别为低风险任务。

#### 实施例五：召回状态控制

系统根据溯源置信度分值和置信度阈值控制候选知识模块的召回状态。召回状态可以包括正常召回、降权召回、附带提示召回、抑制召回和触发重抽取。

在一个实施例中，系统可以执行如下逻辑：

```text
if score >= normal_threshold:
    state = "normal_recall"
elif score >= warning_threshold:
    state = "degraded_recall"
elif score >= suppress_threshold:
    state = "warning_recall"
else:
    state = "suppressed"
```

若候选知识模块被降权召回，系统可以降低其最终排序分值。若候选知识模块被附带提示召回，系统可以在检索结果中附加失效提示或低可信提示。若候选知识模块被抑制召回，系统可以将其从候选结果集中移除。

#### 实施例六：相关性与可信度联合排序

系统可以将溯源置信度分值与候选知识模块的相关性得分共同用于最终排序。相关性得分可以来自关键词匹配、BM25、向量相似度、图关系扩展或历史点击反馈。

最终排序分值可以表示为：

```text
final_score = relevance_score * alpha + provenance_confidence * beta + feedback_score * gamma
```

其中，`alpha`、`beta` 和 `gamma` 可以根据查询任务类型或风险等级动态调整。对于高风险任务，系统可以提高 `beta` 的权重；对于探索任务，系统可以提高 `alpha` 的权重。

#### 实施例七：自动重抽取触发

当候选知识模块满足重抽取触发条件时，系统生成重抽取任务。重抽取触发条件可以包括溯源置信度分值低于重抽取阈值、源文档版本不一致、源片段覆盖率低于覆盖率阈值、候选知识模块在高风险任务中被抑制召回或候选知识模块的失效状态为需要审核或禁止召回。

重抽取任务可以包括：

```text
module_id: 知识模块标识
source_document_id: 源文档标识
source_span_id: 源片段标识
module_section: 模块字段标识
trigger_reason: 触发原因
priority: 任务优先级
```

系统可以将重抽取任务写入队列。重抽取结果可以进入暂存区或审核队列。审核通过后，系统更新对应知识模块、搜索索引、搜索投影和缓存。

#### 实施例八：原因码记录

系统记录每次召回控制的原因码。原因码可以包括源版本不一致、校验值不一致、源片段覆盖不足、抽取时间过期、审核状态不足、失效状态抑制、风险等级阈值不满足等。

原因码可以用于审计、可解释展示、调试和策略优化。例如，当某个模块在高风险任务中被抑制召回时，系统可以记录：

```text
reason_codes:
  - risk_threshold_not_met
  - stale_state_review_required
  - source_version_mismatch
```
