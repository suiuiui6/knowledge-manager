# 给专利代理人的项目与专利布局说明

> 本文用于帮助专利代理人快速理解项目、公开状态、已准备的申请初稿以及后续可拆分的窄改进点。本文不是正式法律意见，请代理人结合现有技术检索、新颖性/创造性判断和申请策略进行修改。

## 1. 项目基本情况

项目名称：Knowledge Manager

项目类型：面向 AI 编程智能体、大语言模型上下文加载和团队知识治理的知识管理系统。

项目定位：把非结构化或半结构化资料（例如产品文档、运行手册、事故复盘、架构说明、Confluence、Notion、Markdown 文件等）转化为可审查、可版本化、可检索、可通过 MCP 加载的结构化知识模块。

核心使用场景：

1. 从外部文档或本地文件中抽取知识，生成结构化知识模块。
2. 对抽取出的模块进行 staging、review、approve 等人工审核流程。
3. 将已审核模块以 JSON 文件和索引形式保存在 Git 原生知识库中。
4. 通过 CLI、HTTP API 或 MCP server 给智能体、大语言模型和开发工具按需加载知识。
5. 在企业场景中接入 Confluence、Notion 等外部源，记录来源、同步状态、风险状态和运维视图。

与普通 RAG 系统的区别：

1. 本项目强调“结构化知识模块”，而不是普通文本 chunk。
2. 本项目强调 Git 原生、可审查、可 diff、可追踪的文件存储。
3. 本项目面向智能体运行时的按需知识加载，而不是单纯问答系统。
4. 本项目具有来源追踪、审核流程、检索策略、失效治理和企业运维视图等治理能力。

## 3. 当前最建议保护的方向

建议围绕“未充分公开的窄改进点”进行申请布局。所谓未充分公开，是指公开资料可能描述过方向，但没有充分公开具体算法、状态机、评分公式、字段级影响传播、阈值联动、任务闭环和技术效果。

当前最强的五个窄改进点如下：

1. 字段级影响传播矩阵。
2. 分级 stale 状态机与检索可见性联动。
3. 溯源置信度评分模型。
4. 高风险任务动态阈值召回控制。
5. 低可信候选自动重抽取闭环。

这五个点和公开基线之间的关系是：公开基线可能已经有 provenance、stale、routing policy 或 source/module view，但上述五点进一步限定到了字段级传播、状态迁移、连续评分、风险阈值和自动修复闭环，更适合作为窄改进方案进行保护。

### A1 初稿

文件：`a1-source-span-impact-staleness-patent-draft.md`

发明名称：

一种基于源片段映射的派生知识模块影响范围判定与分级失效控制方法、装置、电子设备及存储介质。

核心技术问题：

外部源文档发生局部变化时，如何精确判断哪些派生知识模块、哪些模块字段受到影响，并根据影响程度控制失效状态、检索可见性和局部重抽取。

主要技术方案：

1. 将外部源文档解析为多个源片段。
2. 在知识抽取过程中建立 `source_document -> source_span -> module_id -> module_section` 的映射关系。
3. 源文档更新后，基于版本、checksum、标题路径、字符范围、内容摘要等确定源片段变更集合。
4. 根据映射关系把源片段变更传播到派生知识模块和模块字段。
5. 依据变更比例、字段类型、模块置信度、访问频次、任务风险等级等确定分级失效状态。
6. 根据分级失效状态控制检索可见性、排序权重、失效提示、抑制召回或局部重抽取。

建议强调的创新点：

1. 字段级影响传播，而不是文档级或模块级粗粒度 stale。
2. 源片段变化到模块字段的多级映射。
3. 变更影响因子与失效等级的计算。
4. 失效等级与检索可见性、排序、审核、重抽取的联动。
5. 局部重抽取，而不是全量重建。

应避免过宽表述：

1. 不要只写“记录 provenance”。
2. 不要只写“源文档变化后标记 stale”。
3. 不要只写“生成 source/module view”。

### A2 初稿

文件：`a2-provenance-confidence-retrieval-reextract-patent-draft.md`

发明名称：

一种基于溯源置信度的知识模块检索抑制与自动重抽取触发方法、装置、电子设备及存储介质。

核心技术问题：

知识检索阶段如何不仅根据相关性召回模块，还根据模块当前可信程度决定正常召回、降权召回、提示召回、抑制召回或触发重抽取。

主要技术方案：

1. 接收知识检索请求并生成候选知识模块集合。
2. 获取候选模块的溯源元数据，例如源版本、checksum、源片段覆盖率、抽取时间、审核状态、失效状态、模块置信度和历史使用反馈。
3. 根据溯源元数据计算溯源置信度分值。
4. 根据查询任务类型或风险等级确定动态置信度阈值。
5. 根据置信度分值和阈值控制召回状态。
6. 当候选模块满足重抽取触发条件时，根据源文档或源片段生成重抽取任务。
7. 重抽取结果进入暂存区或审核队列，审核通过后更新知识模块、索引和搜索投影。

建议强调的创新点：

1. 连续溯源置信度评分，而不是简单 status/stale 过滤。
2. 相关性得分与溯源置信度联合排序。
3. 高风险任务使用更高可信度阈值。
4. 低可信候选触发局部重抽取。
5. 召回控制原因码用于审计和策略优化。

应避免过宽表述：

1. 不要只写“根据状态过滤搜索结果”。
2. 不要只写“风险等级影响检索策略”。
3. 不要只写“低质量结果重新抽取”。

## 5. 建议的五件专利布局

从策略上看，可以考虑将当前两份初稿作为两个母案方向，再拆出五个窄案。具体是否同日提交、作为独立申请还是先母案后分案，请代理人结合检索和预算判断。

### 5.1 A1-1：字段级影响传播矩阵

建议名称：

一种基于源片段与模块字段映射的派生知识影响范围判定方法、装置、设备及介质。

技术问题：

源文档局部变化后，如何精确定位受影响的派生知识模块字段，而不是把整个文档或整个模块粗粒度标记为失效。

核心方案：

1. 建立源片段、模块、模块字段、检索入口之间的映射矩阵。
2. 源片段变化后，通过矩阵传播得到受影响字段集合。
3. 计算每个字段的影响比例和影响原因。
4. 将影响结果写入索引、搜索投影或审核任务。

适合作为独立权利要求的主句：

一种派生知识影响范围判定方法，包括：建立源片段与派生知识模块字段之间的映射矩阵；响应于源片段发生变化，根据所述映射矩阵确定受影响模块字段集合；根据变化范围和字段类型计算影响值；根据所述影响值更新所述受影响模块字段的检索状态。

### 5.2 A1-2：分级 stale 状态机与检索可见性联动

建议名称：

一种基于分级失效状态机的知识模块检索可见性控制方法、装置、设备及介质。

技术问题：

知识模块失效状态如果只是布尔值，无法区分轻微过期、需要审核、禁止召回、正在重抽取、已恢复等不同技术状态。

核心方案：

1. 定义多个失效状态，例如 `unaffected`、`low_risk_stale`、`review_required`、`suppressed`、`reextracting`、`restored`。
2. 根据源变更、审核结果、重抽取结果和任务风险等级进行状态迁移。
3. 每个状态对应不同检索可见性策略，例如正常召回、降权、提示、抑制、强制伴随证据模块。
4. 状态迁移记录原因码，供审计和策略回放。

适合作为独立权利要求的主句：

一种知识模块检索可见性控制方法，包括：为派生知识模块或其字段配置分级失效状态机；根据源片段变更、审核结果或重抽取结果触发状态迁移；根据迁移后的分级失效状态确定所述派生知识模块或字段的召回、降权、提示或抑制策略。

### 5.3 A2-1：溯源置信度评分模型

建议名称：

一种基于溯源元数据的知识模块可信度评分方法、装置、设备及介质。

技术问题：

检索系统通常只根据相关性排序，无法判断一个高度相关模块在当前时刻是否仍然可信。

核心方案：

1. 获取候选模块的源版本一致性、checksum 一致性、源片段覆盖率、抽取时间衰减、审核状态、失效状态和历史加载反馈。
2. 分别计算版本得分、校验得分、覆盖率得分、新鲜度得分、审核得分、反馈得分和惩罚项。
3. 加权生成溯源置信度分值。
4. 将溯源置信度用于排序、过滤、提示或重抽取触发。

适合作为独立权利要求的主句：

一种知识模块可信度评分方法，包括：获取候选知识模块的溯源元数据；根据所述溯源元数据分别确定版本一致性得分、校验一致性得分、源片段覆盖率得分、新鲜度得分和审核得分；对所述得分进行加权计算，得到所述候选知识模块的溯源置信度分值。

### 5.4 A2-2：高风险任务动态阈值召回控制

建议名称：

一种面向不同任务风险等级的知识模块动态召回阈值控制方法、装置、设备及介质。

技术问题：

同一知识模块在普通浏览场景可以被召回，但在生产部署、权限配置、安全处置等高风险任务中可能不应被召回。

核心方案：

1. 识别查询任务类型或风险等级。
2. 根据风险等级选择不同的溯源置信度阈值或排序权重。
3. 对低于阈值的候选模块执行降权、提示、抑制或强制伴随召回。
4. 记录风险等级与召回控制原因码。

适合作为独立权利要求的主句：

一种知识模块动态召回控制方法，包括：识别知识检索请求对应的任务风险等级；根据所述任务风险等级确定溯源置信度阈值；将候选知识模块的溯源置信度分值与所述溯源置信度阈值比较；根据比较结果确定所述候选知识模块的召回状态。

### 5.5 A2-3：低可信候选自动重抽取闭环

建议名称：

一种检索阶段低可信知识候选的自动重抽取触发与索引回写方法、装置、设备及介质。

技术问题：

检索阶段发现知识模块低可信时，传统系统通常只过滤或提示，无法自动触发修复流程并更新后续检索结果。

核心方案：

1. 检索阶段识别低可信候选模块。
2. 根据候选模块关联的源文档、源片段和模块字段生成重抽取任务。
3. 将重抽取任务进入 staging 或审核队列。
4. 审核通过后更新模块内容、索引、搜索投影和缓存。
5. 记录从抑制到修复的闭环状态。

适合作为独立权利要求的主句：

一种低可信知识候选自动重抽取方法，包括：在知识检索阶段确定低可信候选知识模块；根据所述低可信候选知识模块关联的源片段和模块字段生成重抽取任务；响应于重抽取结果通过审核，更新所述低可信候选知识模块及其检索索引。

## 6. 推荐申请策略

推荐优先顺序：

1. 先评估 A1 母案和 A2 母案是否同日提交。
2. 若预算允许，将 A1-1、A2-1、A2-3 作为最强窄案优先处理。
3. A1-2 和 A2-2 可根据检索结果决定是否独立申请，或作为从属权利要求并入母案。

最建议优先保护的三个窄点：

1. 字段级影响传播矩阵。
2. 溯源置信度评分模型。
3. 低可信候选自动重抽取闭环。

原因：

1. 这三个点分别解决影响范围判定、可信度计算和自动修复闭环问题，技术问题相对独立。
2. 与公开基线相比，它们更窄、更具体，更容易写出可区分的技术特征。
3. 三者可以组合形成完整闭环，但也可以分别主张保护。

## 10. 一句话概括

本项目不是单纯的知识库或 RAG 工具，而是面向智能体和大语言模型上下文加载的结构化知识治理系统。已经公开过的宽泛能力包括知识模块化、MCP 加载、provenance、stale 和 routing policy。建议专利重点转向未充分公开的窄改进：字段级影响传播、分级失效状态机、溯源置信度评分、风险动态阈值召回控制、低可信候选自动重抽取闭环。
