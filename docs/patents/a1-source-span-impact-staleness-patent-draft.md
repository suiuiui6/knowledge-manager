# 发明专利申请文件初稿 A1

> 文档用途：供专利代理人修改、检索和定稿。本文不是正式法律意见，也不建议在未完成新颖性检索和未公开实现确认前直接提交。

## 发明名称

一种基于源片段映射的派生知识模块影响范围判定与分级失效控制方法、装置、电子设备及存储介质

## 摘要

本发明公开了一种基于源片段映射的派生知识模块影响范围判定与分级失效控制方法、装置、电子设备及存储介质。该方法包括：获取外部源文档并将其解析为多个源片段；在知识抽取过程中建立源片段与派生知识模块字段之间的映射关系；在外部源文档更新后，基于源片段的版本、校验值、标题路径、字符范围或内容摘要确定源片段变更集合；根据所述映射关系将源片段变更传播到对应的派生知识模块及模块字段；依据变更比例、字段类型、模块置信度、访问频次或任务风险等级确定分级失效状态；并根据所述分级失效状态控制派生知识模块或模块字段在检索系统中的可见性、排序权重、提示状态或重抽取任务。通过本发明，能够将源文档变更的影响范围从文档级缩小到源片段和模块字段级，减少无关模块被误标记为失效，并降低过期知识被召回到智能体或大语言模型上下文中的概率。

## 权利要求书

1. 一种基于源片段映射的派生知识模块影响范围判定与分级失效控制方法，其特征在于，包括：
   获取外部源文档，并将所述外部源文档解析为多个源片段；
   在基于所述外部源文档生成派生知识模块的过程中，建立所述源片段与所述派生知识模块的模块字段之间的映射关系；
   响应于所述外部源文档发生更新，确定源片段变更集合；
   根据所述映射关系和所述源片段变更集合，确定受影响的派生知识模块及受影响的模块字段；
   根据预设影响因子确定所述受影响的派生知识模块或所述受影响的模块字段的分级失效状态；
   根据所述分级失效状态控制所述派生知识模块或所述模块字段在检索系统中的可见性或排序权重。

3. 根据权利要求 1 所述的方法，其特征在于，所述派生知识模块包括以下至少一种模块字段：概览字段、详情字段、示例字段、引用字段、注意事项字段、标签字段、关联模块字段。

   根据所述映射记录定位对应的派生知识模块；
   根据所述映射记录中记录的字段标识定位所述派生知识模块中的受影响模块字段。

## 说明书

### 技术领域

本发明涉及知识管理、文档同步、信息检索、人工智能辅助软件工程和大语言模型上下文管理领域，尤其涉及一种基于源片段映射的派生知识模块影响范围判定与分级失效控制方法、装置、电子设备及存储介质。

### 背景技术

随着智能体、大语言模型和企业知识管理系统的发展，越来越多的系统会从外部知识源中抽取内容，并将抽取结果整理为结构化知识模块。外部知识源可以包括企业文档系统、协同编辑系统、代码仓库文档、网页、Markdown 文件或运行手册等。结构化知识模块可以被搜索系统、问答系统、智能体或大语言模型按需加载。

在实际使用中，外部源文档经常发生局部更新。例如，某个段落被修改，某个配置项被替换，某个标题下的注意事项被删除，或者某个示例被更新。现有系统通常只能按文档级或模块级记录源文档版本。当源文档变化时，系统难以判断哪些派生知识模块受到影响，更难以判断派生知识模块中的哪些字段受到影响。

这种粗粒度处理方式会带来两个问题。第一，如果系统将源文档变化关联的全部模块都标记为失效，会造成大量无关模块进入审核或重抽取流程，增加计算成本和人工审核成本。第二，如果系统未能识别局部变化对派生模块的影响，过期知识可能继续被检索召回，并被输入到智能体或大语言模型上下文中，造成错误建议或错误执行。

因此，需要一种能够把外部源文档的变更影响从文档级传播到源片段级、模块级和模块字段级的技术方案，并基于影响程度对派生知识模块进行分级失效控制。

### 发明内容

#### 要解决的技术问题

本发明要解决的技术问题是：当外部源文档发生局部变化时，如何精确判断所述局部变化影响到哪些派生知识模块及模块字段，并根据影响程度执行不同级别的失效控制，从而减少不必要的全量重抽取和全量审核，同时降低过期知识被检索召回的概率。

#### 技术方案

为解决上述技术问题，本发明提供一种基于源片段映射的派生知识模块影响范围判定与分级失效控制方法。该方法首先将外部源文档解析为多个源片段，源片段可以由标题路径、段落范围、字符范围、版本、校验值和内容摘要等信息描述。在知识抽取过程中，系统记录每个派生知识模块及其模块字段所依据的源片段，形成源文档、源片段、派生知识模块和模块字段之间的多级映射关系。

当外部源文档发生更新时，系统对更新前后的源片段进行比较，确定源片段变更集合。然后，系统根据源片段变更集合和多级映射关系，将源片段变化传播到对应的派生知识模块和模块字段。对于受影响的模块字段，系统进一步根据变更比例、字段类型、模块置信度、审核状态、访问频次和任务风险等级等影响因子确定分级失效状态。

系统根据分级失效状态对派生知识模块或模块字段执行检索控制。对于低风险失效字段，可以降低排序权重或附加提示；对于需要审核的字段，可以将其召回状态设置为带警告召回或限制召回；对于禁止召回的字段或模块，可以从候选结果中抑制。系统还可以根据受影响模块字段生成局部重抽取任务，仅对受影响字段执行重抽取。

#### 有益效果

与现有技术相比，本发明至少具有以下有益效果：

1. 能够将源文档更新的影响范围从文档级缩小到源片段级和模块字段级，减少无关模块被误判为失效。
2. 能够根据影响程度进行分级处理，避免在轻微变化场景下触发高成本的全量重抽取。
3. 能够将失效状态与检索可见性、排序权重和重抽取任务联动，降低过期知识被输入到智能体或大语言模型上下文的概率。
4. 能够通过源文档视图和模块视图提供双向追踪能力，提高知识治理和审核效率。

### 具体实施方式

以下结合附图和实施例对本发明进行说明。应当理解，所描述的实施例仅用于解释本发明，而不用于限定本发明的保护范围。

#### 实施例一：源片段解析

在本实施例中，系统从外部知识源获取源文档。外部知识源可以是 Confluence、Notion、Git 仓库文档、Markdown 文件、网页或其他文档系统。系统对源文档进行结构化解析，将源文档划分为多个源片段。

每个源片段可以包括源文档标识、源文档版本、源文档校验值、标题路径、段落标识、字符起始位置、字符结束位置、内容摘要、外部链接和更新时间中的至少一种。例如，一个源片段可以表示为：

```text
source_id: "team-runbook"
document_id: "deploy-guide"
version: "v42"
checksum: "8d23..."
heading_path: ["Deployment", "Rollback"]
char_start: 1200
char_end: 1680
excerpt_hash: "4fb1..."
```

通过上述源片段描述方式，系统能够在源文档发生局部变化后定位变化发生的位置。

#### 实施例二：映射关系建立

系统在基于源文档生成派生知识模块时，记录每个知识模块及其字段所依据的源片段。派生知识模块可以包括概览字段、详情字段、示例字段、引用字段、注意事项字段、标签字段和关联模块字段。

映射关系可以表示为：

```text
source_document -> source_span -> module_id -> module_section
```

其中，`module_section` 表示模块字段，例如 `overview`、`details`、`examples` 或 `caveats`。一个源片段可以对应多个模块字段，一个模块字段也可以由多个源片段共同生成。

#### 实施例三：源片段变更集合确定

当系统再次同步同一外部源文档时，系统获取更新后的源片段集合，并与更新前的源片段集合进行比较。比较方式可以包括版本比较、校验值比较、标题路径比较、字符范围比较、内容摘要比较或语义摘要比较。

当某个源片段满足预设变更条件时，系统将该源片段加入源片段变更集合。预设变更条件可以包括校验值不同、内容摘要相似度低于阈值、字符范围发生重排、标题路径被删除或源文档版本发生变化。

#### 实施例四：影响范围传播

系统根据源片段变更集合查找映射关系，定位所有受影响的派生知识模块及受影响的模块字段。对于一个发生变化的源片段，系统可以依次查找其关联的模块标识和字段标识，并生成影响记录。

影响记录可以包括：

```text
module_id: "deployment/rollback-policy"
section: "caveats"
source_span: "deploy-guide#rollback"
change_type: "modified"
impact_ratio: 0.62
```

系统可以将多个影响记录合并为模块级影响摘要。模块级影响摘要用于确定分级失效状态、更新索引、生成审核任务或触发局部重抽取。

#### 实施例五：分级失效状态确定

系统根据预设影响因子确定分级失效状态。预设影响因子可以包括源片段变更比例、源片段变更位置、模块字段类型、派生知识模块置信度、审核状态、最近访问频次、查询任务类型或查询任务风险等级。

例如，当受影响字段为注意事项字段且查询任务风险等级较高时，即使源片段变更比例较低，系统也可以将其设置为需要审核或禁止召回。当受影响字段为示例字段且模块置信度较高时，系统可以将其设置为低风险失效，并在检索时降低排序权重。

分级失效状态可以包括：

```text
unaffected: 未受影响
low_risk_stale: 低风险失效
review_required: 需要审核
suppressed: 禁止召回
```

#### 实施例六：检索控制

系统在执行知识检索时读取派生知识模块或模块字段的分级失效状态。对于未受影响的模块字段，系统按正常排序逻辑处理。对于低风险失效的模块字段，系统降低其排序权重或附加失效提示。对于需要审核的模块字段，系统可以限制其在高风险任务中的召回。对于禁止召回的模块字段或模块，系统将其从候选结果集中移除。

在一个实施例中，系统可以对检索候选结果执行如下控制：

```text
if stale_state == "suppressed":
    remove_from_candidates()
elif stale_state == "review_required" and task_risk == "high":
    remove_from_candidates()
elif stale_state == "low_risk_stale":
    reduce_rank_score()
```

#### 实施例七：局部重抽取

当受影响模块字段达到重抽取条件时，系统生成局部重抽取任务。局部重抽取任务可以包括源文档标识、源片段标识、模块标识、模块字段标识、失效原因和重抽取优先级。

系统执行局部重抽取后，可以将重抽取结果进入暂存区或审核队列。审核通过后，系统更新派生知识模块对应字段，并同步更新搜索索引、搜索投影、缓存或知识图谱。

#### 实施例八：双向视图

系统可以生成源文档视图和模块视图。源文档视图展示每个源文档或源片段影响的派生知识模块。模块视图展示每个派生知识模块依赖的源文档或源片段以及当前分级失效状态。通过双向视图，审核人员可以快速定位某个源文档更新对知识库造成的影响，也可以从某个模块追溯其来源。

## 提交前处理事项

1. 需要确认 A1 的新增实现尚未公开，尤其是“模块字段级影响传播”“分级 stale”“检索可见性联动”和“局部重抽取”部分。
2. 公开代码中已有基础 provenance、source span、stale 标记和双视图能力，正式申请时应避免把这些已公开内容作为唯一创新点。
3. 建议在提交前补充至少一个未公开实验数据，例如局部变更场景下减少的重抽取比例、减少的误召回比例或审核任务减少比例。
4. 建议代理人围绕“源片段变化到模块字段的影响传播算法”做现有技术检索。
