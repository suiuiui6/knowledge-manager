## 可重复的具体失败

隔离语料为文档原有的 Prerequisites、Install、Verify、Infrastructure Verification、Rollback 五个抽取模块。配置显式声明 `operations` 必带 `operations/single-node-deploy-001`。

查询 `systemctl install`，`limit=2`：实际 search_modules 返回 Install 与 Verify，遗漏 Prerequisites；简单规则返回 Install 与 Prerequisites，仍遵守上限 2。原文的前提来自 Prerequisites 中先安装基础包的说明；规则按类别设置，是诊断控制而非自动推断。

源码机制：快照 `inputs/knowledge-manager/src/knowledge_manager/storage.py` 的 search_modules，先执行 `scored[:limit]`，随后追加配套模块，最后 `return results[:limit]`。因此配套规则未保证在最终返回集中保留。仅扩大上限不能作为同预算新方法效果。

来源定位机制：快照 source_ingestion.py 的 _stamp_module 对每个模块使用 `page.body_text[:200]`，覆盖原模块的来源跨度。Install 原文单位在 [161,2072)，Verify 在 [2072,4276)；固定前缀不能完整覆盖它们。这里不声称整个模块无来源，只说明当前给出的局部证据没有对应到完整抽取单位。

## 为什么仍未立题

1. 明确目标版本下的过滤是简单基线；19/19 是源身份规则的机械结果，不能视为新模型精度。
2. 配套依赖已显式给定，“先保留，再截断”属于直接工程策略。没有证明依赖发现、版本兼容性和预算之间存在难以被强方法解决的联合问题。
3. 精确摘录可用字符串定位；更难的生成式摘要、多源支持尚未测量，不能把它们的潜在困难写成实验发现。
4. 本轮未运行语义重排、图/超图检索、传播式记忆基线、真实 Agent 或软件操作。不能据此声称击败 Hyper-RAG、CUPMem 或其他论文方法。
