## 现有方法对比表（计划）

| 对照路线 | 要控制的条件 | 用途 |
|---|---|---|
| 原始文档chunk BM25 | 同源资料、查询、token预算、语言处理与证据标注 | 比较词法检索下的端到端方案 |
| 同内容模块BM25 | 与模块组共享内容，只改变组织粒度 | 隔离排序实现与内容整理影响 |
| 本地dense/hybrid检索（可用性待查） | 记录模型与参数、同源资料、预算一致 | 强检索对照；未运行不能报复现结果 |
| 实际Knowledge Manager | 锁定代码版本，调用实际search_modules链路 | 正式系统组 |
| 模块结构、关联补全、审核消融 | 其余环节与内容尽量固定；单独记录人工整理成本 | 识别每个机制的独立影响 |

## 改进方向（AI推断）

以可追溯源证据为标注单位，研究“模块组织 + 可审查入库 + 受控关联补全”在软件任务中的覆盖率、可靠性及成本。必须分离结构、排序、审核文本改善和关联扩展影响，不将不同检索器或更多上下文带来的优势归给模块结构。创新性需外部文献与全文核对。
